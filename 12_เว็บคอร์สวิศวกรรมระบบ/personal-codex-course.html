  • Tool Use — ความสามารถของ AI ในการเรียกใช้โปรแกรมภายนอก เช่น รันคำสั่ง Bash, ค้นหาไฟล์, เรียก API แทนการตอบจากความรู้เดิมอย่างเดียว
    • 
          
  • File Context — เนื้อหาของไฟล์เฉพาะที่ถูกส่งเข้าไปให้ AI อ่านในงานนั้น เช่น ไฟล์ .c, .ino, schematic export
    • 
          
  • Repository Context — โครงสร้างทั้งโปรเจกต์ (โฟลเดอร์ ไฟล์ history การเชื่อมโยงระหว่างโมดูล) ที่ AI ต้องสำรวจก่อนสรุปผล ไม่ใช่แค่ไฟล์เดียว
    • 
          
  • Read vs. Edit Permission — งานตรวจสอบ (Review) ควรให้สิทธิ์ "อ่านเท่านั้น" ส่วนงานแก้ไขไฟล์จริงต้องระบุสิทธิ์ "แก้ไข" อย่างชัดเจนและจำกัดเฉพาะไฟล์ที่เกี่ยวข้อง
    • 
          
  • คำสั่ง vs. การวิเคราะห์ vs. การลงมือทำ — "ตรวจสอบ" (Inspect) ต่างจาก "วิเคราะห์สาเหตุ" (Analyze) และต่างจาก "แก้ไขให้" (Act) ต้องระบุให้ชัดว่าต้องการขั้นไหน ไม่เช่นนั้น AI อาจลงมือแก้ไขทั้งที่ผู้ใช้ต้องการเพียงความเห็น
    • 
          
  • ความเสี่ยงจากการให้ AI แก้ไขไฟล์โดยไม่มีขอบเขต — หากไม่กำหนด Scope และ Stop Condition อาจเกิดการแก้ไขไฟล์ที่ไม่เกี่ยวข้อง เขียนทับค่า Configuration หรือแก้ไขเกินคำขอ โดยเฉพาะในไฟล์ Firmware และ Wiring ที่กระทบความปลอดภัยได้โดยตรง
    •

    • 
          
  • Web HMI: ให้ AI ใช้ Repository Context สำรวจโครงสร้างโฟลเดอร์ frontend/backend ก่อน แล้วรายงานว่าไฟล์ใดเกี่ยวข้องกับหน้าจอ Alarm ก่อนเริ่มแก้ไข

5 · Prompt สำเร็จรูป

        
Role: Embedded Firmware Reviewer
Context: โปรเจกต์ STM32 ควบคุมมอเตอร์ DC ผ่าน PWM
Objective: ตรวจสอบไฟล์ motor_control.c เพื่อหาสาเหตุที่มอเตอร์สั่นผิดปกติ
Scope: อ่านเฉพาะไฟล์ motor_control.c และ motor_control.h เท่านั้น
Constraints: ห้ามแก้ไขไฟล์ใด ๆ ในขั้นตอนนี้ ห้ามเดาโดยไม่มีหลักฐานจากโค้ด
Required Actions: อ่านโค้ด ระบุจุดที่น่าสงสัย พร้อมอ้างอิงเลขบรรทัด
Expected Output: รายการสมมติฐานสาเหตุ เรียงตามความเป็นไปได้
Acceptance Criteria: ทุกสมมติฐานต้องอ้างอิงโค้ดจริง ไม่ใช่การคาดเดาทั่วไป
Stop Conditions: หยุดรอการยืนยันก่อนเสนอวิธีแก้ไข

    • 
          
  • Context คือข้อมูลพื้นหลังของงาน — ไม่ใช่คำสั่ง แต่เป็นสิ่งที่ AI ต้อง "รู้ก่อน" จึงจะตัดสินใจได้ถูก
    •

    • 
          
  • Constraints คือข้อห้ามหรือเงื่อนไขบังคับ เช่น ห้ามแก้ไขไฟล์ ห้ามสมมติค่าที่ไม่มีแหล่งอ้างอิง
    •

    • 
          
  • Expected Output ระบุรูปแบบผลลัพธ์ (ตาราง, รายการ, โค้ด, รายงาน) ไม่ใช่แค่เนื้อหา
    • 
          
  • Acceptance Criteria คือเกณฑ์ที่ใช้ตัดสินว่างาน "ผ่าน" หรือ "ไม่ผ่าน" ต้องตรวจสอบได้จริง ไม่ใช่ความรู้สึก
    • 
          
  • Validation Method ระบุวิธีที่จะยืนยันผลลัพธ์ เช่น เทียบกับ Datasheet, รันทดสอบจริง, ให้ผู้เชี่ยวชาญตรวจ

5 · Prompt สำเร็จรูป — วิเคราะห์ Root Cause

        
Role: Maintenance Diagnostic Analyst
Context: มอเตอร์สายการผลิตร้อนผิดปกติเป็นระยะ ไม่คงที่
Objective: วิเคราะห์ Root Cause จาก Error Log และ Maintenance Record
Scope: อ่านเฉพาะไฟล์ log 30 วันล่าสุด และบันทึกซ่อมบำรุงที่เกี่ยวข้อง
Constraints: ห้ามสรุปสาเหตุเดียวโดยไม่เปรียบเทียบทางเลือกอื่น ห้ามสมมติค่าที่ไม่มีในข้อมูล
Required Process: Discovery → Inspection → Analysis เท่านั้น (ยังไม่ Design)
Expected Output: ตารางสมมติฐานสาเหตุ เรียงตามความเป็นไปได้ พร้อมหลักฐานอ้างอิง
Acceptance Criteria: ทุกสมมติฐานต้องอ้างอิงข้อมูล log หรือ record จริง
Stop Conditions: หยุดรอการยืนยันก่อนเข้าสู่ขั้นตอน Design

    • 
          
  • แยกข้อเท็จจริงออกจากข้อสันนิษฐาน — สิ่งที่มาจากเอกสารจริง (Fact) ต้องแยกจากสิ่งที่ AI อนุมานเอง (Inference/Assumption) อย่างชัดเจนในรายงาน
    • 
          
  • ระบุข้อมูลที่ยังไม่ยืนยัน — หากไม่มีแหล่งอ้างอิงรองรับ ต้องระบุว่า "ยังไม่ยืนยัน" แทนการเดา
    • 
          
  • ห้ามสร้างค่าทางวิศวกรรมขึ้นเอง — ค่าพิกัด กระแส แรงดัน หรือค่าความปลอดภัยต้องมาจากเอกสารจริงเท่านั้น
    •

  • ตัวเลขสรุปตรวจสอบย้อนกลับไปยังข้อมูลต้นฉบับได้หรือไม่
    • 
        

      


      

        
9 · ข้อผิดพลาดที่พบบ่อย

        
    
          
  • ให้ AI ลบ Outlier ทิ้งโดยอัตโนมัติทั้งที่บางค่าคือเหตุการณ์จริงที่ต้องสนใจ
    • 
          
  • สร้าง Dashboard ที่ไม่มี Timestamp หรือ Data Source กำกับ ทำให้ตรวจสอบย้อนกลับไม่ได้
    • 
          
  • คำนวณสถิติจากข้อมูลที่ยังไม่ผ่าน Data Cleaning
    • 
        

      


      

        
10 · แบบทดสอบท้ายบท

        
    
          
  • เพราะเหตุใด Outlier จึงต้องพิจารณาก่อนลบ ไม่ใช่ลบทิ้งทันที
    • 
          
  • Validation Note ใน Dashboard มีประโยชน์อย่างไรต่อผู้ใช้งานจริง
    • 
          
  • ยกตัวอย่างความแตกต่างระหว่าง KPI และ Trend ในบริบทข้อมูล Motor Current
    • 
        

      


      

        
11 · การสร้างรายงานอัตโนมัติ

        
เมื่อ Workflow วิเคราะห์ข้อมูลทำซ้ำได้แล้ว สามารถให้ Codex สร้างรายงานสรุปประจำสัปดาห์/เดือนโดยอัตโนมัติจากไฟล์ข้อมูลชุดใหม่ โดยใช้ Prompt Template เดียวกันกับหัวข้อที่ 5 เพียงเปลี่ยนไฟล์ Input

      


      

        
12 · งานประยุกต์กับโปรเจกต์จริง

        
นำข้อมูล Motor Current, Temperature หรือ Downtime จากเครื่องจักรจริงในงานมาผ่าน Workflow เต็มรูปแบบ ตั้งแต่ Data Cleaning จนถึงออกแบบ Dashboard 1 ชุด สำหรับใช้ติดตามจริงในทีม

      

    


    
    

      
M6
การใช้ Codex ตามบทบาทงาน


      

        
1 · วัตถุประสงค์การเรียนรู้

        
    
          
  • ออกแบบ Prompt ที่ปรับตามบทบาทงาน (Role-based Prompting) แทนการใช้ Prompt แบบทั่วไปซ้ำทุกงาน
    • 
          
  • ระบุขอบเขตงาน ข้อมูลนำเข้า และเกณฑ์ตรวจรับที่เหมาะกับแต่ละบทบาทได้
    • 
        

      


      

        
2 · แนวคิดสำคัญ

        
แต่ละบทบาทต้องระบุ: เป้าหมาย, ขอบเขตงาน, ข้อมูลนำเข้า, ขั้นตอนการทำงาน, ผลลัพธ์, เกณฑ์ตรวจรับ, ข้อควรระวัง

      


      

        
3 · นิยามบทบาท (10 Roles)


        

          
ROLE 01
Electrical Engineer

          

            
เป้าหมายตรวจสอบวงจรและตู้ควบคุมไฟฟ้าให้ถูกต้องตามมาตรฐาน

            
ขอบเขตงานSingle Line Diagram, Wiring Diagram, การเลือกขนาดอุปกรณ์ป้องกัน

            
ข้อมูลนำเข้าแบบไฟฟ้า, พิกัดโหลด, มาตรฐานที่อ้างอิง (เช่น IEC)

            
ขั้นตอนการทำงานตรวจสอบขนาดสาย → ตรวจ Breaker → ตรวจ Protection Coordination

            
ผลลัพธ์รายการจุดที่ไม่เป็นไปตามมาตรฐาน พร้อมข้อเสนอแนะ

            
เกณฑ์ตรวจรับทุกข้อเสนอแนะอ้างอิงมาตรฐานหรือ Datasheet จริง

            
ข้อควรระวังห้ามอนุมัติค่าพิกัดความปลอดภัยโดยไม่มี Safety Review จากมนุษย์

          

        


        

          
ROLE 02
Embedded Firmware Engineer

          

            
เป้าหมายตรวจสอบและปรับปรุงคุณภาพโค้ด Firmware

            
ขอบเขตงานไฟล์ .c/.h เฉพาะโมดูลที่เกี่ยวข้องกับปัญหา

            
ข้อมูลนำเข้าSource Code, Register Map, Error Log

            
ขั้นตอนการทำงานอ่านโค้ด → ระบุจุดเสี่ยง → เสนอแนวทางแก้ (ยังไม่แก้จริง)

            
ผลลัพธ์รายการจุดเสี่ยงพร้อมเลขบรรทัดอ้างอิง

            
เกณฑ์ตรวจรับทุกข้อสังเกตอ้างอิงโค้ดจริง ไม่ใช่การคาดเดาทั่วไป

            
ข้อควรระวังห้ามแก้ไข Register หรือ Timing-critical code โดยไม่ทดสอบจริงบนฮาร์ดแวร์

          

        


        

          
ROLE 03
PCB Design Engineer

          

            
เป้าหมายตรวจสอบ Layout และ Design Rule ของ PCB

            
ขอบเขตงานSchematic, Footprint, Layer Stack-up

            
ข้อมูลนำเข้าGerber/Schematic Export, BOM, Datasheet ของ IC หลัก

            
ขั้นตอนการทำงานตรวจ Footprint → ตรวจระยะห่าง Trace → ตรวจ Power/Ground Plane

            
ผลลัพธ์รายการจุดที่เสี่ยงต่อ Signal Integrity หรือ Thermal Issue

            
เกณฑ์ตรวจรับอ้างอิง Design Rule หรือคำแนะนำจาก Datasheet ของ IC โดยตรง

            
ข้อควรระวังห้ามยืนยันความถูกต้องทาง EMC โดยไม่มีการทดสอบจริง

          

        


        

          
ROLE 04
Automation Engineer

          

            
เป้าหมายตรวจสอบ Logic การควบคุม PLC/HMI ให้ทำงานตามลำดับที่ถูกต้อง

            
ขอบเขตงานLadder Logic, Sequence Diagram, Interlock Condition

            
ข้อมูลนำเข้าโปรแกรม PLC, I/O List, Process Description

            
ขั้นตอนการทำงานตรวจ Sequence → ตรวจ Interlock → ตรวจ Alarm Logic

            
ผลลัพธ์รายการเงื่อนไขที่ขาดหรือขัดแย้งกัน

            
เกณฑ์ตรวจรับทุกข้อสังเกตอ้างอิง Logic จริงในโปรแกรม

            
ข้อควรระวังห้ามแก้ไข Safety Interlock โดยไม่มี Safety Review

          

        


        

          
ROLE 05
Test Engineer

          

            
เป้าหมายออกแบบและตรวจสอบผลการทดสอบเทียบกับ Acceptance Criteria

            
ขอบเขตงานTest Plan, Test Case, ผลการทดสอบจริง

            
ข้อมูลนำเข้าRequirement Spec, ผลทดสอบดิบ (Raw Data)

            
ขั้นตอนการทำงานสร้าง Test Case → เทียบผลกับเกณฑ์ → สรุปผ่าน/ไม่ผ่าน

            
ผลลัพธ์Test Report พร้อมหลักฐานอ้างอิงทุกกรณี

            
เกณฑ์ตรวจรับผลสรุปทุกข้อมีข้อมูลทดสอบจริงรองรับ

            
ข้อควรระวังห้ามสรุปว่า "ผ่าน" โดยไม่มีข้อมูลทดสอบประกอบ

          

        


        

          
ROLE 06
Maintenance Engineer

          

            
เป้าหมายวิเคราะห์สาเหตุความเสียหายและวางแผนซ่อมบำรุง

            
ขอบเขตงานMaintenance Record, Error Log, Spare Part List

            
ข้อมูลนำเข้าประวัติการซ่อม, ข้อมูล Sensor, คู่มือเครื่องจักร

            
ขั้นตอนการทำงานรวบรวมประวัติ → หารูปแบบ (Pattern) → เสนอ Preventive Plan

            
ผลลัพธ์แผนบำรุงรักษาเชิงป้องกัน พร้อมรอบเวลาที่แนะนำ

            
เกณฑ์ตรวจรับแผนอ้างอิงคู่มือผู้ผลิตหรือประวัติจริง ไม่ใช่ค่าเดา

            
ข้อควรระวังห้ามลดรอบบำรุงรักษาต่ำกว่าคำแนะนำของผู้ผลิตโดยไม่มีเหตุผลรองรับ

          

        


        

          
ROLE 07
Project Engineer

          

            
เป้าหมายติดตามความคืบหน้าโครงการเทียบกับแผนงาน

            
ขอบเขตงานProject Timeline, Task List, Budget

            
ข้อมูลนำเข้าแผนงาน (Gantt), รายงานความคืบหน้ารายสัปดาห์

            
ขั้นตอนการทำงานเทียบแผนกับผลจริง → ระบุงานล่าช้า → เสนอความเสี่ยง

            
ผลลัพธ์สรุปสถานะโครงการและความเสี่ยงที่ต้องติดตาม

            
เกณฑ์ตรวจรับตัวเลขความคืบหน้าตรงกับข้อมูลที่รายงานจริง

            
ข้อควรระวังห้ามประเมินสถานะ "จะเสร็จตามแผน" โดยไม่มีข้อมูลสนับสนุน

          

        


        

          
ROLE 08
Technical Writer

          

            
เป้าหมายจัดทำเอกสารส่งมอบงานให้ครบถ้วนและเข้าใจง่าย

            
ขอบเขตงานManual, Report, Drawing Note

            
ข้อมูลนำเข้าข้อมูลทางเทคนิคที่ผ่านการตรวจสอบแล้วจากบทบาทอื่น

            
ขั้นตอนการทำงานจัดโครงเอกสาร → เรียบเรียงเนื้อหา → ตรวจความสอดคล้อง

            
ผลลัพธ์เอกสารฉบับสมบูรณ์พร้อมส่งมอบ

            
เกณฑ์ตรวจรับเนื้อหาสอดคล้องกับข้อมูลต้นทางทุกจุด ไม่มีการเติมข้อมูลใหม่

            
ข้อควรระวังห้ามสร้างข้อมูลทางเทคนิคใหม่ในระหว่างเรียบเรียง

          

        


        

          
ROLE 09
Data Analyst

          

            
เป้าหมายแปลงข้อมูลดิบเป็นข้อมูลสรุปที่ใช้ตัดสินใจได้

            
ขอบเขตงานไฟล์ข้อมูลที่ระบุไว้เท่านั้น

            
ข้อมูลนำเข้าCSV/Excel/JSON จากระบบเก็บข้อมูลเครื่องจักร

            
ขั้นตอนการทำงานตามที่ระบุใน Module 5 (Cleaning → Outlier → Summary)

            
ผลลัพธ์ตารางสรุปและกราฟที่ตรวจสอบย้อนกลับได้

            
เกณฑ์ตรวจรับตัวเลขสรุปตรงกับข้อมูลต้นฉบับ

            
ข้อควรระวังห้ามตีความสาเหตุเชิงสาเหตุ-ผลลัพธ์เกินกว่าที่ข้อมูลสนับสนุน

          

        


        

          
ROLE 10
Engineering Manager

          

            
เป้าหมายสรุปภาพรวมงานและความเสี่ยงสำหรับการตัดสินใจระดับบริหาร

            
ขอบเขตงานสรุปจากรายงานของบทบาทอื่นทั้งหมด ไม่ลงรายละเอียดเชิงเทคนิคลึก

            
ข้อมูลนำเข้ารายงานจาก Project/Test/Maintenance Engineer

            
ขั้นตอนการทำงานรวบรวมรายงาน → จัดลำดับความสำคัญ → สรุป Executive Summary

            
ผลลัพธ์Executive Summary พร้อมข้อเสนอเชิงตัดสินใจ

            
เกณฑ์ตรวจรับทุกข้อสรุปอ้างอิงรายงานต้นทางที่ระบุได้

            
ข้อควรระวังห้ามให้ AI ตัดสินใจเชิงนโยบายหรืองบประมาณแทนมนุษย์

          

        

      


      

        
4 · แบบฝึกหัด

    • 
          
  • ทดลองสลับบทบาทเดียวกันไปใช้กับงานคนละประเภท เพื่อดูว่า Constraints และ Acceptance Criteria ต้องปรับอย่างไร
    • 
        

      


      

        
5 · ผลลัพธ์ที่ต้องส่ง

        
Prompt 1 ชุดที่ออกแบบตามบทบาทที่เลือก พร้อมระบุ Acceptance Criteria และข้อควรระวังของบทบาทนั้นครบถ้วน

      


      

        
6 · ข้อผิดพลาดที่พบบ่อย

    • 
          
  • ให้บทบาทหนึ่งตัดสินใจข้ามขอบเขตของอีกบทบาท เช่น ให้ Data Analyst สรุปเชิงนโยบายแทน Engineering Manager
    •

สร้างชุด Prompt ตามบทบาทสำหรับทีมของตนเอง อย่างน้อย 3 บทบาทที่ใช้งานจริงบ่อยที่สุด เก็บไว้เป็น Reusable Template สำหรับ Module 12 (การทำงานร่วมกับทีม)

3 · ทฤษฎีและหลักการ

        
    
          
  • Prompt Chaining — แบ่งงานใหญ่เป็น Prompt ย่อยหลายชุดที่ส่งต่อผลลัพธ์กัน แทนการยัดทุกอย่างไว้ใน Prompt เดียว ทำให้ตรวจสอบแต่ละขั้นตอนได้ง่ายขึ้น
    • 
          
  • Task Decomposition — เทคนิคเดียวกับ Module 3 แต่นำมาฝังไว้ในโครงสร้าง Prompt โดยตรง เพื่อให้ AI ประมวลผลทีละขั้นแทนการกระโดดข้าม
    • 
          
  • Few-shot Prompting — ให้ตัวอย่างผลลัพธ์ที่ถูกต้อง 1-2 ตัวอย่างก่อนให้ AI ทำงานจริง ช่วยควบคุมรูปแบบผลลัพธ์ให้สม่ำเสมอ
    • 
          
  • Structured Output / JSON Schema — กำหนดโครงสร้างผลลัพธ์ตายตัว เหมาะกับงานที่ต้องนำผลไปใช้ต่อในระบบอื่น เช่น Dashboard
    • 
          
  • Self-Review / Critic Prompt — สั่งให้ AI ตรวจสอบผลลัพธ์ของตัวเองอีกครั้งในบทบาทนักวิจารณ์ ก่อนส่งคำตอบสุดท้าย
    • 
          
  • Verification Prompt — Prompt แยกต่างหากที่ใช้ตรวจทานผลลัพธ์จาก Prompt ก่อนหน้า เทียบกับ Acceptance Criteria
    • 
          
  • Context Management — เลือกส่งเฉพาะไฟล์/ข้อมูลที่จำเป็นในแต่ละขั้นตอน ป้องกัน Context Window ล้นหรือ AI สับสนกับข้อมูลเก่า
    • 
          
  • Prompt Version Control — เก็บประวัติการแก้ไข Prompt เพื่อย้อนกลับได้เมื่อเวอร์ชันใหม่ให้ผลแย่ลง
    • 
          
  • Error Recovery — กำหนดวิธีที่ AI ควรทำเมื่อพบข้อมูลไม่ครบหรือขัดแย้งกัน แทนการเดาเพื่อให้ได้คำตอบ
    • 
          
  • Stop Conditions — จุดที่ต้องหยุดรอการยืนยันจากมนุษย์ก่อนดำเนินการขั้นต่อไป (ต่อเนื่องจากหลักการใน Module 3)
    • 
        

      


      

        
4 · ตัวอย่างจากงานวิศวกรรม

5 · Prompt สำเร็จรูป — Critic / Verification Prompt

        
Role: Independent Reviewer (Critic)
Context: ตรวจทานผลการวิเคราะห์ Design Rule จาก Prompt ก่อนหน้า
Objective: ตรวจสอบว่าข้อสรุปแต่ละข้อมีหลักฐานอ้างอิงรองรับจริงหรือไม่
Inputs: ผลลัพธ์จาก Prompt วิเคราะห์ Design Rule (แนบมาทั้งหมด)
Constraints: ห้ามแก้ไขข้อสรุปเอง ให้ระบุเฉพาะจุดที่ขาดหลักฐาน
Required Process: ไล่ตรวจทีละข้อ → ทำเครื่องหมายข้อที่ไม่มีอ้างอิงชัดเจน
Expected Output: รายการข้อที่ต้องแก้ไขหรือเพิ่มหลักฐาน
Acceptance Criteria: ทุกข้อที่ถูกทักท้วงต้องระบุเหตุผลชัดเจน
Stop Conditions: หยุดรอการแก้ไขจากรอบวิเคราะห์เดิมก่อนสรุปเป็นรายงานฉบับสมบูรณ์

5 · นิยามไฟล์ SKILL.md ฉบับสมบูรณ์ (Production-Ready Template)

        
---
name: stm32-firmware-reviewer
description: ตรวจสอบโค้ด STM32 Firmware ด้าน Interrupt Safety, DMA Race Condition และ MISRA-C Guidelines
version: 1.2.0
---

## ROLE & AUTHORITY
คุณคือ Principal Embedded Safety Auditor ตรวจสอบโค้ดระดับ Bare-metal/HAL สำหรับ STM32 MCUs

## SCOPE & CONSTRAINTS
1. ตรวจสอบเฉพาะไฟล์ .c และ .h ที่ส่งเข้ามา ห้ามแก้ไขไฟล์ต้นฉบับเด็ดขาด (Read-only)
2. ทุกข้อผิดพลาดต้องระบุเลขบรรทัด (Line Number) พร้อมชื่อ Register จริง เช่น TIM1->CR1, NVIC->IP
3. หากพบการใช้ delay ฟังก์ชันหน่วงเวลา (HAL_Delay) ภายใน ISR (Interrupt Handler) ให้จัดเป็น CRITICAL BUG ทันที
4. ห้ามสรุปว่าโค้ดสมบูรณ์หากยังไม่พบการจัดการ Watchdog (IWDG/WWDG)

## REQUIRED REVIEW PIPELINE
1. NVIC Priority & ISR Latency Audit: ตรวจสอบความสัมพันธ์ของ Preemption Priority ระหว่าง Safety-critical interrupts กับ Peripheral อื่น
2. DMA & Memory Barrier: ตรวจสอบตัวแปรที่แชร์ระหว่าง ISR กับ Main loop ว่ามี `volatile` หรือ Memory Barrier หรือไม่
3. Register Configuration Validation: ตรวจสอบ Clock Enable, Pin Multiplexing (AFIO/MODER), Timer Prescaler

## OUTPUT SPECIFICATION
ส่งผลลัพธ์เป็น JSON Object ตาม Schema ที่กำหนดเท่านั้น ห้ามพิมพ์คำทักทาย

การวัด Productivity, Quality Metrics และ ROI ทางวิศวกรรม

      
การประเมินผลสัมฤทธิ์และผลตอบแทนจากการลงทุน (ROI) ในการนำ AI Agent มาใช้ในงานวิศวกรรมอย่างเป็นรูปธรรมด้วยข้อมูลเชิงปริมาณ วัดทั้งเวลาที่ประหยัดได้ อัตราการลดลงของข้อบกพร่อง (Defect Escape Rate) และต้นทุนรวม (TCO)

  • วัดผลด้านคุณภาพเชิงวิศวกรรม: First-Pass Yield (FPY) ของ PCB Layout และ MTBF ของเฟิร์มแวร์
    • 
          
  • นำเสนอรายงาน Productivity & Financial Impact Dashboard ต่อผู้บริหารระดับสูงได้อย่างน่าเชื่อถือ

2 · แนวคิดสำคัญและตัวชี้วัดเชิงปริมาณ

        

          
ตัวชี้วัดนิยามและการคำนวณเป้าหมายอุตสาหกรรม

          
Cycle Time Reductionระยะเวลาตั้งแต่วิเคราะห์สเปกจนถึงปิดงาน (Baseline vs AI-Assisted)ลดลง 35% – 50%

          
First-Pass Yield (FPY)เปอร์เซ็นต์ของ PCB หรือโค้ดที่ผ่านการทดสอบรอบแรกโดยไม่ต้องนำกลับมาแก้ไขเพิ่มขึ้น > 85%

          
Rework Ratio(เวลาที่ใช้แก้โค้ดที่ AI สร้าง / เวลาทั้งหมดของงานนั้น) × 100ต้องต่ำกว่า 20%

          
Defect Escape Rateจำนวนข้อบกพร่องที่หลุดรอดจากขั้นตอน Review ไปถึงขั้นตอนการผลิตจริงลดลง > 60%

        

      


      

        
3 · ทฤษฎีและสมการคำนวณทางการเงิน

        

          

            
สมการการประหยัดเวลาและผลิตภาพ

            
Time Saved (hrs) = T_baseline − T_ai_assisted

Productivity Gain (%) =
  ((T_baseline − T_ai_assisted) / T_baseline) × 100

Effective Hourly Value = 
  Time Saved × Engineer Hourly Rate ($/hr)

          

          

            
สมการคำนวณ ROI สุทธิ

            
Net Financial Benefit = 
  (Time Saved × Hourly Rate) + Downtime Prevented Value

Total AI Cost = 
  Subscription + API Tokens + Human Review Time

ROI (%) = 
  ((Net Benefit − Total AI Cost) / Total AI Cost) × 100

คู่มือความปลอดภัยเชิงหน้าที่สำหรับระบบควบคุมเครื่องจักรวิกฤตตามมาตรฐาน IEC 61508 และ ISO 13849-1 พร้อมตารางถอดรหัสข้อผิดพลาดระดับรีจิสเตอร์ของ ARM Cortex-M Processor (SCB->CFSR, HFSR, MMFAR, BFAR)


      

        
1 · การแมประดับความปลอดภัย: Performance Level (PL) vs Safety Integrity Level (SIL)

        

          
ISO 13849-1 (PL)IEC 61508 / 62061 (SIL)ความน่าจะเป็นที่จะเกิดอันตรายต่อชั่วโมง (PFH_D)สถาปัตยกรรมวงจรขั้นต่ำที่บังคับ

          
PL aไม่มีระดับเทียบเท่า10^-5 ถึง < 10^-4Category B / 1 (Single Channel)

          
PL bSIL 13 x 10^-6 ถึง < 10^-5Category 1 (ใช้ชิ้นส่วนเกรด Well-tried)

          
PL cSIL 110^-6 ถึง < 3 x 10^-6Category 2 หรือ 3 (มีระบบทดสอบหรือ Redundancy)

          
PL dSIL 210^-7 ถึง < 10^-6Category 3 (Dual Channel Redundancy พร้อมตัดวงจรเมื่อเกิด 1 Fault)

2 · สมการคำนวณความน่าเชื่อถือและความปลอดภัยเชิงหน้าที่

        

          

            
สมการคำนวณ Diagnostic Coverage (DC)

            
DC = (Sum of Lambda_DD / Sum of Lambda_D_total) * 100

เกณฑ์ระดับการครอบคลุม:
- DC < 60%:           None (ไม่มีระบบตรวจสอบ)
- 60% <= DC < 90%:   Low (ระดับต่ำ)
- 90% <= DC < 99%:   Medium (ระดับปานกลาง)
- DC >= 99%:          High (ระดับสูง - บังคับสำหรับ PL e)

          

          

            
สมการ Safe Failure Fraction (SFF)

            
SFF = (Sum Lambda_S + Sum Lambda_DD) / (Sum Lambda_S + Sum Lambda_D)

โดยที่:
- Lambda_S:  อัตราการเสียแบบปลอดภัย (Safe Failures)
- Lambda_DD: อัตราการเสียแบบอันตรายที่ตรวจจับได้ (Dangerous Detected)
- Lambda_DU: อัตราการเสียแบบอันตรายที่ตรวจจับไม่ได้ (Dangerous Undetected)

          

        

      


      

        
3 · ตารางถอดรหัสบิตรีจิสเตอร์ความผิดพลาด ARM Cortex-M (Fault Status Map)

        

          
รีจิสเตอร์ช่วงบิต (Bitfield)ชื่อแฟล็ก (Flag Name)สาเหตุทางวิศวกรรม (Root Cause)แนวทางแก้ไข (Remediation)

SCB->CFSRBusFault [15]BFARVALIDแอดเดรสใน SCB->BFAR มีค่าถูกต้องอ่านค่าจาก SCB->BFAR เพื่อตรวจสอบรีจิสเตอร์ที่เกิดบัสเออเรอร์

สูตรคณิตศาสตร์และสมการการแปลงพิกัดเวกเตอร์สำหรับการควบคุมมอเตอร์แบบ Field Oriented Control (FOC), การคำนวณ Space Vector PWM (SVPWM), การชดเชย Inverter Dead-time และการออกแบบวงจรวัดกระแส Shunt


      

        
1 · การแปลงพิกัดทางคณิตศาสตร์ในระบบ FOC (Vector Transformations)

        

          

            
การแปลง Clarke Transform (3-Phase ไปยัง 2-Phase Stationary)

            
แปลงกระแส 3 เฟสที่ห่างกัน 120 องศา (Ia, Ib, Ic) เข้าสู่แกนตั้งฉาก Alpha-Beta (90 องศา):

            
i_alpha = i_a
i_beta  = (1 / sqrt(3)) * (i_a + 2 * i_b)
        = 0.577350269 * (i_a + 2 * i_b)

// ในกรณีที่จุด Neutral ไม่ต่อลงดิน (Ia + Ib + Ic = 0):
i_c = -(i_a + i_b)

          

          

            
การแปลง Park Transform (Stationary ไปยัง Synchronous Rotor Frame)

            
แปลงพิกัด Alpha-Beta เข้าสู่แกน d-q ที่หมุนไปพร้อมกับโรเตอร์ด้วยมุม Theta (Electrical Angle):

            
i_d =  i_alpha * cos(theta) + i_beta * sin(theta)
i_q = -i_alpha * sin(theta) + i_beta * cos(theta)

โดยที่:
- i_d: กระแสแกนตรง (สร้างสนามแม่เหล็ก Flux) เป้าหมาย = 0 ใน SPM
- i_q: กระแสแกนตั้งฉาก (สร้างแรงบิดมอเตอร์ Torque)

          

        


        

          
การแปลง Inverse Park Transform (Synchronous กลับเป็น Stationary)

          
แปลงแรงดันสั่งการ Vd, Vq ที่คำนวณจาก PI Controllers กลับมาเป็น Valpha, Vbeta เพื่อป้อนเข้า SVPWM Modulator:

          
v_alpha = v_d * cos(theta) - v_q * sin(theta)
v_beta  = v_d * sin(theta) + v_q * cos(theta)

        

      


      

        
2 · อัลกอริทึม Space Vector PWM (SVPWM) และการคำนวณ Dwell Time

        

          
ขั้นตอนสมการและตรรกะคำอธิบาย

          
1. Sector DeterminationA = (Vbeta > 0); B = (sqrt(3)*Valpha - Vbeta > 0); C = (-sqrt(3)*Valpha - Vbeta > 0);
Sector = A + 2*B + 4*C;		คำนวณว่าเวกเตอร์แรงดันอ้างอิงตกอยู่ในเซกเตอร์ใด (1 ถึง 6) ในระนาบวงกลมหกเหลี่ยม

          
2. Dwell Times (T1, T2)T1 = (sqrt(3) * T_pwm / V_dc) * (Valpha * sin(n*pi/3) - Vbeta * cos(n*pi/3));
T2 = (sqrt(3) * T_pwm / V_dc) * (-Valpha * sin((n-1)*pi/3) + Vbeta * cos((n-1)*pi/3));		คำนวณเวลาในการเปิด Active Voltage Vectors สองเวกเตอร์ที่อยู่ติดกัน

          
3. Zero Vector (T0)T0 = T_pwm - T1 - T2;
Ta_on = T0/4; Tb_on = Ta_on + T1/2; Tc_on = Tb_on + T2/2;		กระจายเวลา Zero Vector (V0, V7) แบบ Symmetric เพื่อลดค่า Total Harmonic Distortion (THD)

        

      


      

        
3 · การชดเชยเวลาหน่วงของอินเวอร์เตอร์ (Dead-Time Compensation)

        

          

            
ปัญหาจาก Dead-Time (Shoot-through Prevention)

            
การเว้นเวลา Dead-Time (เช่น 1.0 ถึง 1.5 ไมโครวินาที) ระหว่าง High-Side และ Low-Side MOSFET ทำให้เกิดแรงดันตกคร่อมและฮาร์มอนิกลำดับที่ 5, 7 ในกระแสมอเตอร์ ส่งผลให้เกิดอาการกระตุกที่ความเร็วต่ำ (Torque Ripple)

          

          

            
สมการการชดเชยแรงดัน (Voltage Compensation)

            
Delta_V = (t_dead / T_pwm) * V_dc

V_phase_comp = V_phase_ref + Delta_V * sign(I_phase)

โดยที่:
- sign(I_phase) = +1 เมื่อกระแสไหลออกจากอินเวอร์เตอร์เข้าสู่มอเตอร์
- sign(I_phase) = -1 เมื่อกระแสไหลย้อนกลับเข้าสู่อินเวอร์เตอร์

          

        

      


      

        
4 · การคำนวณขนาดตัวต้านทานวัดกระแส (Current Shunt Resistor Design)

        

          
พารามิเตอร์สมการคำนวณตัวอย่างค่าจริง (มอเตอร์ 20A Peak, 3.3V ADC)

          
ค่าความต้านทาน (R_shunt)R_shunt = V_adc_max / (Gain_opamp * I_peak)สมมติ Op-Amp Gain = 10, V_max = 1.65V: R = 1.65 / (10 * 20) = 0.00825 Ohm (เลือก 8 mOhm)

          
กำลังสูญเสียความร้อน (P_loss)P = (I_rms)^2 * R_shuntที่กระแส 14A RMS: P = 14^2 * 0.008 = 1.57 Watt (ต้องเลือก Shunt ขนาด 3W ถึง 5W เพื่อความทนทาน)

          
การเดินลายวงจร (Kelvin Connection)4-Wire Sense (แยกเส้นแรงดัน Sense ออกจากเส้นกระแสหลัก)คู่สาย Differential Sense ต้องเดินชิดกันและขนานกัน เพื่อหักล้างการเหนี่ยวนำแม่เหล็ก (Inductive Loop)

        

      

    

    
    

      
A7
High-Speed PCB Layout, EMI/EMC Compliance & Signal Integrity

      
คู่มือมาตรฐานการออกแบบแผ่นวงจรพิมพ์ความเร็วสูง (High-Speed PCB Design) และการทดสอบความเข้ากันได้ทางแม่เหล็กไฟฟ้า (EMC Testing) ตามมาตรฐานสากล CISPR 32, IEC 61000-4-x, การคำนวณอิมพีแดนซ์สายส่งสัญญาณ Microstrip/Stripline, การจัดการระนาบกราวด์ และการป้องกัน Transient Spikes


      

        
1 · มาตรฐานการทดสอบความเข้ากันได้ทางแม่เหล็กไฟฟ้าในภาคอุตสาหกรรม (EMC Standards Matrix)

        

          
มาตรฐานสากลชื่อการทดสอบ (Test Category)เงื่อนไขและระดับความรุนแรง (Severity Levels)ผลกระทบและการป้องกันทางวิศวกรรม

          

            CISPR 32 / EN 55032
            Radiated & Conducted Emissions
            Class A (โรงงานอุตสาหกรรม) vs Class B (ที่อยู่อาศัย / เชิงพาณิชย์ เข้มงวดกว่า 10dB)
            ป้องกันการแผ่คลื่นรบกวนออกสู่อากาศ: ใช้ Ground Plane หนาแน่น, ติดตั้ง Common Mode Choke บนพอร์ตสัญญาณ
          

          

            IEC 61000-4-2
            Electrostatic Discharge (ESD) Immunity
            Level 4: Contact Discharge ±8 kV, Air Discharge ±15 kV (Rise time < 1 ns)
            ป้องกันชิปพังจากไฟฟ้าสถิต: ติดตั้ง TVS Diode ชิดจุดสัมผัสภายนอก (Conector) โดยเดินสายแบบ Kelvin ไม่ให้มี Stub
          

          

            IEC 61000-4-4
            Electrical Fast Transient / Burst (EFT)
            Level 3/4: ±2 kV บนสายจ่ายไฟ AC/DC, ±1 kV บนสายควบคุม/สื่อสาร (Pulse repetition 5 kHz / 100 kHz)
            ป้องกันไมโครคอนโทรลเลอร์รีเซ็ตจากประกายไฟหน้าสัมผัสรีเลย์: ติดตั้ง RC Snubber และ Ferrite Bead บนสายสัญญาณ
          

          

            IEC 61000-4-5
            Surge Immunity (Lighting & Switching)
            Combination Wave 1.2/50 µs (Open Circuit), 8/20 µs (Short Circuit): Line-Line 1 kV, Line-PE 2 kV
            ป้องกันแรงดันกระชากจากฟ้าผ่า: วงจรป้องกัน 3 ขั้น (Gas Discharge Tube -> Inductor -> MOV -> Bidirectional TVS)
          

          

            IEC 61000-4-6
            Conducted RF Immunity
            150 kHz ถึง 80 MHz, ระดับแรงดัน 10 Vrms มอดูเลตด้วย 1 kHz 80% AM
            คลื่นวิทยุเหนี่ยวนำเข้าสายเคเบิล: กราวด์สาย Shield ทั้งสองฝั่ง (360-degree EMC Cable Gland) ป้องกัน Ground Loop
          

        

      


      

        
2 · การคำนวณอิมพีแดนซ์ของสายส่งสัญญาณความเร็วสูง (Transmission Line Equations)

        

          

            
Microstrip Single-Ended Impedance (Z0)

            
สำหรับสัญญาณ Single-Ended (เช่น Clock, UART, SPI, SDIO) บนเลเยอร์ผิวนอกติดกับ Ground Plane:

            
Z_0 = [87 / sqrt(epsilon_r + 1.41)] * ln[ 5.98 * h / (0.8 * w + t) ]

โดยที่:
- h: ความหนาของไดอิเล็กทริก (Dielectric height ถึงระนาบ GND)
- w: ความกว้างของเส้นทองแดง (Trace width)
- t: ความหนาทองแดง (Copper thickness, 1 oz = 0.035 mm)
- epsilon_r: Relative Permittivity ของวัสดุ PCB (FR-4 ≈ 4.2 ถึง 4.5)

          

          

            
Edge-Coupled Differential Microstrip (Zdiff)

            
สำหรับคู่สัญญาณ Differential (USB 90Ω, RS-485 120Ω, Ethernet 100Ω, CAN 120Ω):

            
Z_diff ≈ 2 * Z_0 * [ 1 - 0.48 * exp( -0.96 * s / h ) ]

โดยที่:
- s: ระยะห่างระหว่างคู่สัญญาณ (Trace separation)
- กฎ 3W: ให้เว้นระยะห่างระหว่างคู่สัญญาณกับเส้นอื่น ≥ 3 เท่าของความกว้าง trace เพื่อลด Crosstalk

          

        


        

          
กฎความยาววิกฤต (Critical Length) และการ Termination

          
หากความยาวลายวงจรยาวเกินความยาววิกฤต สัญญาณจะเริ่มแสดงพฤติกรรมเป็นสายส่งคลื่น (Transmission Line) ซึ่งจะเกิดการสะท้อนของคลื่น (Wave Reflection) และ Ringing:

          
L_crit = t_rise / (2 * t_pd)

ในวัสดุ FR-4 (t_pd ≈ 6.8 ps/mm หรือ 170 ps/inch):
- หาก MCU GPIO Slew Rate t_rise = 2 ns:
  L_crit = 2000 ps / (2 * 6.8 ps/mm) = 147 mm (≈ 14.7 cm)
- หากเส้นทางยาวกว่า 14.7 cm: จำเป็นต้องต่อตัวต้านทานอนุกรม (Series Source Termination Resistor):
  R_series = Z_0 - R_driver_output

        

      


      

        
3 · เส้นทางกระแสไหลกลับและการตัดระนาบกราวด์ (Return Current Paths & Split Planes)

        

          

            
การกระจายตัวของกระแสไหลกลับความถี่สูง (Skin Effect & Return Current)

            
ที่ความถี่สูง (> 100 kHz) กระแสไหลกลับใน Ground Plane จะไม่เลือกเดินทางตามเส้นทางที่ความต้านทานต่ำสุด (DC Path) แต่จะเลือกเดินทางตามเส้นทางที่มี ค่าความเหนี่ยวนำต่ำสุด (Minimum Inductance Path) ซึ่งก็คือพื้นที่บน Ground Plane ที่อยู่ใต้เส้นสัญญาณพอดี

            
ความลึกของ Skin Depth ในเนื้อทองแดง:
delta = sqrt( rho / (pi * f * mu) )
ที่ความถี่ 100 MHz: delta ≈ 6.6 ไมโครเมตร

ความหนาแน่นกระแสไหลกลับ j(x):
j(x) = (I_0 / (pi * h)) * [ 1 / (1 + (x/h)^2) ]
กระแส 80% กระจุกตัวในขอบเขต ±3h ใต้เส้นสัญญาณ

          

          

            
ข้อห้ามวิกฤต: ห้ามเดินสายสัญญาณตัดผ่านรอยแยก Ground Plane (Split Plane Crossing)

            
เมื่อสัญญาณความเร็วสูงพาดผ่านรอยแยกของระนาบกราวด์ กระแสไหลกลับจะไม่สามารถเดินทางตรงได้ ทำให้เกิดลูปกระแสขนาดใหญ่ (Inductive Loop Area) ส่งผลให้เกิดการแผ่รังสีสนามแม่เหล็ก (EMI Emissions) เพิ่มขึ้น 20 ถึง 40 dB และเกิด Signal Distortion รุนแรง

            
แนวทางแก้ไขเมื่อหลีกเลี่ยงไม่ได้:
1. เดินสายสัญญาณผ่านทางอื่นโดยไม่ข้ามรอยแยก
2. วาง Stitching Capacitor (100nF High-frequency Ceramic) คร่อมรอยแยก ณ จุดที่สัญญาณตัดผ่าน
3. เปลี่ยนเลเยอร์สัญญาณโดยวาง Ground Stitching Via ติดกับ Signal Via ทันที

          

        

      


      

        
4 · สถาปัตยกรรมการต่อ TVS Diode และการวาง Decoupling Capacitor

        

          
หัวข้อหลักการวิศวกรรมที่ถูกต้องข้อผิดพลาดที่พบบ่อย (Anti-pattern)

          

            TVS Diode Placement
            วาง TVS Diode ติดกับขา Connector มากที่สุด และเดินลายวงจรให้สัญญาณ วิ่งทะลุ Pad ของ TVS ก่อน เข้าสู่วงจรภายใน (Kelvin Routing)
            ต่อแยกเป็นกิ่งก้าน (T-Stub): เหนี่ยวนำแรงดันเกินตกคร่อมขา stub V = L*(di/dt) ทำให้แรงดันสไปก์ทะลุเข้า MCU (Stub 2mm ≈ 2nH × 30A/ns = 60V เกินพิกัด!)
          

          

            Decoupling Capacitor Network
            ใช้คาปาซิเตอร์หลายขนาดยูนิตขนานกัน เช่น 10µF (Bulk) ∥ 100nF (Mid) ∥ 1nF (High-freq RF) เพื่อกดค่า PDN Impedance ให้ต่ำตลอดช่วงความถี่
            ใช้ค่าเดียวทั้งหมด หรือวางห่างจากขาไฟของชิปเกิน 5 mm ทำให้ค่าความเหนี่ยวนำของ Via (L_via ≈ 0.8 nH) ทำลายประสิทธิภาพการบายพาส
          

          

            Via-in-Pad & Power Fanout
            เจาะ Via สำหรับ Ground ของ Decoupling Capacitor ให้อยู่ข้าง Pad โดยตรง และเจาะ 2 รูขนานกันเพื่อลดค่า Parasitic Inductance ลงครึ่งหนึ่ง
            ลากสายทองแดงเส้นเล็กๆ ยาวๆ ออกจาก Pad ก่อนจะลง Via ซึ่งเพิ่มค่าความเหนี่ยวนำอย่างมีนัยสำคัญ
          

        

      

    


    
    

      
A8
Hard Real-Time OS (RTOS) Determinism & Concurrency Engineering

      
คู่มือสถาปัตยกรรมระบบปฏิบัติการเวลาจริง (Hard Real-Time Operating Systems) บนสถาปัตยกรรม ARM Cortex-M: เจาะลึกกลไก Context Switching ผ่าน PendSV, การแยกสแต็ก MSP/PSP, การจัดการลำดับความสำคัญของ Interrupts ใน FreeRTOS/Zephyr, การแก้ปัญหา Priority Inversion และทฤษฎี Rate Monotonic Scheduling (RMS)


      

        
1 · สถาปัตยกรรม Context Switching บน ARM Cortex-M ผ่านข้อยกเว้น PendSV

        

          

            
การทำงานสองสแต็ก (Dual-Stack Architecture: MSP vs PSP)

            
ARM Cortex-M มีสแต็กพอยน์เตอร์ 2 ชุด เพื่อความปลอดภัยและแยกส่วนการทำงาน:

            
    
              
  • MSP (Main Stack Pointer): ใช้งานใน Handler Mode (ISRs ทั้งหมด) และ OS Kernel Scheduler
    • 
              
  • PSP (Process Stack Pointer): ใช้งานเฉพาะใน Thread Mode สำหรับ Tasks / Threads ของแอปพลิเคชัน
    • 
            

            
เมื่อเกิด Exception ซีพียูจะทำการบันทึกรีจิสเตอร์อัตโนมัติด้วยฮาร์ดแวร์ (Hardware Auto-Stacking) ลงบนสแต็กของงานปัจจุบัน:

            
ลำดับการเซฟฮาร์ดแวร์ (8 Registers, 32 Bytes):
[SP-4]  xPSR
[SP-8]  PC (Program Counter / Return Address)
[SP-12] LR (Link Register)
[SP-16] R12
[SP-20] R3
[SP-24] R2
[SP-28] R1
[SP-32] R0 <-- ตำแหน่ง SP ใหม่

          

          

            
กลไก PendSV (Pended Service Call)

            
PendSV ถูกออกแบบมาเพื่อทำ Context Switch โดยตั้งระดับความสำคัญไว้ต่ำสุด (Lowest Priority) เพื่อป้องกันการดีเลย์ของ Interrupt อื่นๆ:

            
/* FreeRTOS PendSV Handler (ARM Assembly) */
__attribute__((naked)) void PendSV_Handler(void) {
  __asm volatile (
    "mrs r0, psp                
" // อ่าน PSP ปัจจุบัน
    "isb                        
"
    "ldr r3, =pxCurrentTCB      
" // โหลด Pointer งานปัจจุบัน
    "ldr r2, [r3]               
"
    "stmdb r0!, {r4-r11}        
" // เซฟ R4-R11 ลงสแต็กงานเดิม
    "str r0, [r2]               
" // บันทึก Top of Stack ลง TCB
    
    "stmdb sp!, {r3, r14}       
"
    "cpsid i                    
" // ป้องกันการแทรกแซง
    "bl vTaskSwitchContext      
" // เลือกงานถัดไปที่มี Priority สูงสุด
    "cpsie i                    
"
    "ldmia sp!, {r3, r14}       
"
    
    "ldr r1, [r3]               
" // โหลด TCB ของงานใหม่
    "ldr r0, [r1]               
" // โหลด SP ของงานใหม่
    "ldmia r0!, {r4-r11}        
" // คืนค่า R4-R11
    "msr psp, r0                
" // เซ็ต PSP ให้งานใหม่
    "isb                        
"
    "bx r14                     
" // คืนค่าด้วย EXC_RETURN ฮาร์ดแวร์จะป๊อป R0-R3,R12,LR,PC,xPSR
  );
}

          

        

      


      

        
2 · การจัดกลุ่ม Interrupt Priorities และความปลอดภัยใน FreeRTOS

        

          
พารามิเตอร์ใน FreeRTOSConfig.hการคำนวณและค่าจริงบน STM32 (4 Priority Bits)กฎเหล็กทางวิศวกรรม (Engineering Hard Rules)

          

            configPRIO_BITS
            4 บิต (STM32 ใช้บิต [7:4] ของ NVIC_IPR, ค่า 0 ถึง 15)
            ARM กำหนดให้เลข 0 คือความสำคัญสูงสุด และ 15 คือความสำคัญต่ำสุด
          

          

            configKERNEL_INTERRUPT_PRIORITY
            (15 << (8 - 4)) = 0xF0 (Priority ต่ำสุด = 15)
            ใช้สำหรับ SysTick และ PendSV เพื่อให้ Interrupt ฝั่งฮาร์ดแวร์ทำงานก่อนเสมอ
          

          

            configMAX_SYSCALL_INTERRUPT_PRIORITY
            (5 << (8 - 4)) = 0x50 (Priority ระดับ = 5)
            แบ่งขอบเขต Interrupt เป็น 2 กลุ่ม: Unmasked (0..4) vs FreeRTOS Managed (5..15)
          

        


        

          
🚨 กฎวิกฤต: ห้ามเรียก FreeRTOS API จาก ISR ที่มี Priority เหนือกว่า MAX_SYSCALL

          

            หาก ISR มีความสำคัญสูงกว่า configMAX_SYSCALL_INTERRUPT_PRIORITY (เช่น ระดับ 0 ถึง 4) ISR นั้นจะไม่ถูกบล็อกโดย FreeRTOS Critical Sections ทำให้มี Real-time Jitter เป็นศูนย์ (Zero Latency) แต่ ห้ามเรียกใช้ฟังก์ชัน FreeRTOS API ใดๆ โดยเด็ดขาด (แม้กระทั่งฟังก์ชันลงท้ายด้วย FromISR) เพราะจะทำให้ Critical Section ถูกทำลายและเกิด HardFault จาก Task List Corruption ทันที!
          

        

      


      

        
3 · ปัญหา Priority Inversion และโซลูชัน Priority Inheritance Mutex

        

          

            
กรณีศึกษา: ความล้มเหลวของ Mars Pathfinder (Unbounded Priority Inversion)

            
เกิดจาก Task ระดับต่ำ (Low Priority) ถือครอง Mutex ข้อมูลบัส แต่ถูกขัดจังหวะโดย Task ระดับกลาง (Medium Priority) ที่ไม่ต้องใช้ Mutex นั้น ทำให้ Task ระดับสูง (High Priority) ที่กำลังรอ Mutex ถูกบล็อกและไม่สามารถทำงานได้ตามกำหนดเวลา ส่งผลให้ Watchdog Timer ตัดการทำงานและรีบูตระบบซ้ำๆ

          

          

            
โซลูชัน: Priority Inheritance Protocol (PIP)

            
เมื่อ Task สูงต้องการ Mutex ที่ Task ต่ำถืออยู่ ระบบจะยกระดับความสำคัญของ Task ต่ำขึ้นมาให้เท่ากับ Task สูงเป็นการชั่วคราว เพื่อให้ Task ต่ำทำงานและปล่อย Mutex ให้เร็วที่สุด โดย Task กลางจะไม่สามารถ Preempt ได้

            
// การสร้าง Mutex ที่มี Priority Inheritance:
SemaphoreHandle_t xMutex = xSemaphoreCreateMutex();

// ห้ามใช้ Binary Semaphore สำหรับการปกป้อง Resource:
// SemaphoreHandle_t xSem = xSemaphoreCreateBinary(); 
// <-- ไม่มี Priority Inheritance! ก่อให้เกิด Priority Inversion

          

        

      


      

        
4 · ทฤษฎี Rate Monotonic Scheduling (RMS) และโหมด Tickless Idle

        

          
หัวข้อสมการและทฤษฎีการนำไปปฏิบัติจริง

          

            Liu & Layland Utilization Bound
            U = Σ (C_i / T_i) ≤ n * (2^(1/n) - 1)
เมื่อ n → ∞: U ≤ ln(2) ≈ 69.3%		
            หากผลรวมของ (Execution Time / Period) ของทุก Task ไม่เกิน 69.3% และมอบหมายให้ Task ที่มีคาบเวลาสั้นที่สุดได้ Priority สูงสุด รับประกันได้ทางคณิตศาสตร์ว่าจะไม่มีการตก Deadline (Zero Deadline Miss)
          

          

            Tickless Idle (configUSE_TICKLESS_IDLE)
            T_sleep = (Next_Task_Wake_Time - Current_Time)
vTaskStepTick(Suppressed_Ticks);		
            เมื่อไม่มีงานใดพร้อมรัน ระบบจะหยุดการทำงานของ SysTick และตั้ง Low-Power Timer (LPTIM) เพื่อปลุก CPU เท่าที่จำเป็น ช่วยลดการกินกระแสจาก 15mA เหลือ < 25µA ในโหมด Sleep
          

        

      

    


  
    
    

      
A9
Power Semiconductor Thermal Design & Safe Operating Area (SOA)

      
คู่มือการออกแบบระบายความร้อนสำหรับเพาเวอร์เซมิคอนดักเตอร์ (MOSFET, SiC, IGBT): เจาะลึกการคำนวณการสูญเสียกำลังงาน Conduction vs Switching Losses, เครือข่ายแบบจำลองความต้านทานความร้อน Foster และ Cauer RC Ladder, การวิเคราะห์ขอบเขตพื้นที่ปลอดภัย Safe Operating Area (SOA) และเทคนิคการขับเกต Active Miller Clamp


      

        
1 · การคำนวณกำลังสูญเสียความร้อนในอินเวอร์เตอร์ (Power Dissipation Analysis)

        

          
ประเภทการสูญเสีย (Loss Mechanism)สมการคณิตศาสตร์และตัวแปรแนวทางการลดความร้อนทางวิศวกรรม

          

            MOSFET Conduction Loss (P_cond)
            P_cond = (I_rms)^2 * R_ds(on)(T_j)
โดยที่ R_ds(on)(T_j) = R_25 * (1 + alpha * (T_j - 25))		
            เลือกอุปกรณ์ที่มีค่า R_ds(on) ต่ำ และระวังค่า Positive Temp Coefficient (ความต้านทานเพิ่มขึ้น 1.5–2 เท่าที่ 125°C)
          

          

            Switching Loss (P_sw)
            P_sw = (E_on + E_off) * f_sw = 0.5 * V_dc * I_peak * (t_rise + t_fall) * f_sw
            ลดเวลา Rise/Fall Time โดยเลือก Gate Driver ที่มีกระแสขับ Peak สูง และลดค่า External Gate Resistor
          

          

            Diode Reverse Recovery (P_rec)
            P_rec = 0.25 * Q_rr * V_dc * f_sw = 0.5 * I_rrm * t_rr * V_dc * f_sw
            เลือกใช้ Body Diode ความเร็วสูง (Fast Recovery) หรือเปลี่ยนเป็น SiC Schottky Diode ซึ่งมีค่า Q_rr ใกล้ศูนย์
          

          

            Gate Drive Loss (P_gate)
            P_gate = Q_g * V_gate * f_sw (สูญเสียความร้อนบน Gate Driver IC)
            เลือก MOSFET ที่มี Total Gate Charge (Q_g) ต่ำ หรือลดแรงดันขับเกตลงตามสเปก V_gs(th)
          

        

      


      

        
2 · เครือข่ายความต้านทานความร้อนแบบคงตัวและชั่วขณะ (Thermal Impedance Modeling)

        

          

            
การคำนวณอุณหภูมิรอยต่อแบบคงตัว (Steady-State Junction Temperature)

            
สมการความต้านทานความร้อนอนุกรมจากชิปสารกึ่งตัวนำออกสู่บรรยากาศภายนอก:

            
T_j = T_a + P_total * ( R_th_jc + R_th_cs + R_th_sa )

โดยที่:
- T_j: อุณหภูมิรอยต่อภายในชิป (ห้ามเกิน 150°C หรือ 175°C)
- T_a: อุณหภูมิแวดล้อมรอบตู้ควบคุม (ออกแบบที่ 50°C)
- R_th_jc: ความต้านทานความร้อนจาก Junction ถึง Case (ดู Datasheet)
- R_th_cs: ความต้านทานของแผ่นนำความร้อน (Sil-Pad หรือ Thermal Paste ≈ 0.2 ถึง 0.5 K/W)
- R_th_sa: ความต้านทานความร้อนของฮีตซิงก์สู่บรรยากาศ (Heatsink to Ambient)

          

          

            
แบบจำลองชั่วขณะ (Transient Thermal Impedance: Foster vs Cauer RC)

            
ในช่วงเวลาสั้นๆ เช่น การเร่งความเร็วหรือกระแสกระชาก ชิปจะยังไม่ร้อนขึ้นทันทีเนื่องจากมีความจุความร้อน (Thermal Capacitance C_th):

            
Z_th(t) = Sigma [ R_i * (1 - exp(-t / tau_i)) ]
โดยที่ tau_i = R_i * C_i

ประโยชน์ทางวิศวกรรม:
ช่วยให้สามารถ Overload มอเตอร์ที่กระแส 200% ถึง 300% 
ได้เป็นเวลาสั้นๆ (เช่น 2 วินาที) โดยที่ T_j ไม่ทะลุพิกัดจำกัด

          

        

      


      

        
3 · ขอบเขตพื้นที่การทำงานที่ปลอดภัย (Safe Operating Area - SOA Boundaries)

        

          
ขอบเขตบนกราฟ SOAสาเหตุทางฟิสิกส์ (Failure Mechanism)มาตรการป้องกันความเสียหาย (Protection Rule)

          

            1. Ohmic Region Limit
            จำกัดด้วยค่า R_ds(on) สูงสุดของช่องนำกระแส ไม่สามารถจ่ายกระแสเกินกว่า V_ds / R_ds(on) ได้
            ไม่มีความเสียหาย เป็นขีดจำกัดทางธรรมชาติของเซมิคอนดักเตอร์
          

          

            2. Bond Wire Limit
            กระแสพัลส์สูงสุดที่จะไม่ทำให้ลวดทองคำ/อะลูมิเนียมเชื่อมต่อขาชิปหลอมละลาย (Bond Wire Fusing)
            ตั้งค่า Fast Hardware Overcurrent (OCP) Comparator ตัดการทำงานภายใน < 1.5 ไมโครวินาที
          

          

            3. Thermal Limit (P_max)
            ความร้อนสะสมทำให้รอยต่อทะลุขีดจำกัด T_j(max) = 175°C จนสารกึ่งตัวนำสูญเสียความเป็นฉนวน
            ติดตั้งเซนเซอร์ NTC วัดอุณหภูมิที่ฮีตซิงก์ และเขียนอัลกอริทึมลดกระแส (Thermal Derating)
          

          

            4. Spirito Effect / 2nd Breakdown
            เกิดจุดความร้อนเฉพาะจุด (Current Crowding / Hot-spotting) ในโหมด Linear ที่แรงดัน V_ds สูง
            หลีกเลี่ยงการแช่ MOSFET ให้อยู่ในโหมด Linear นานเกิน 100 µs และเปิด-ปิดเกตอย่างรวดเร็ว
          

        

      


      

        
4 · การออกแบบวงจรขับเกตและการป้องกัน Active Miller Clamp

        

          

            
ปัญหา Parasitic dv/dt Turn-on (Shoot-Through Hazard)

            
เมื่อสวิตช์ตัวบนเปิดอย่างรวดเร็ว แรงดัน V_ds ของสวิตช์ตัวล่างจะพุ่งขึ้นด้วย dv/dt สูงมาก ทำให้เกิดกระแสไหลผ่านความจุ Parasitic Miller Capacitance (C_gd):

            
I_miller = C_gd * (dv_ds / dt)
V_gate_spike = I_miller * ( R_driver_sink + R_gate_int )

หาก V_gate_spike > V_gs(th): สวิตช์ตัวล่างจะเปิดเองโดยไม่ได้สั่ง 
ส่งผลให้เกิดการลัดวงจรระหว่างไฟบวกและกราวด์ (Cross-Conduction Shoot-through)!

          

          

            
แนวทางการแก้ไขด้วย Active Miller Clamp

            
ใช้วงจรขับเกตที่มีขา CLAMP โดยตรง เมื่อตรวจพบว่าแรงดันเกตลดลงต่ำกว่า 2.0V ขา Clamp จะเปิดทรานซิสเตอร์ความต้านทานต่ำ (< 0.5 Ω) เพื่อลัดขา Gate ลง Ground ทันที ป้องกันไม่ให้แรงดัน Miller ยกขาลอยขึ้นมาได้

            
เกณฑ์การเลือก Gate Driver IC:
- มีฟังชันก์ Active Miller Clamp ภายในตัว (เช่น STGAP2, ISO5852)
- มีขา Desaturation Detection (DESAT) ตรวจจับการลัดวงจร
- มีฟังก์ชัน Soft Turn-Off (STO) ลดแรงดันไฟเกินตอนปลดโหลด

          

        

      

    


    
    

      
A10
Industrial Cybersecurity & Secure Boot Reference (IEC 62443)

      
คู่มือมาตรฐานความมั่นคงปลอดภัยไซเบอร์ในระบบควบคุมและระบบสมองกลฝังตัวอุตสาหกรรม (Industrial Embedded Cybersecurity) ตามมาตรฐานสากล IEC 62443 และ ISO 21434: ครอบคลุมสถาปัตยกรรมรากฐานความน่าเชื่อถือ Hardware Root of Trust, การแบ่งส่วนความปลอดภัยด้วย ARM TrustZone-M และ MPU, การอัปเดตเฟิร์มแวร์ปลอดภัย (Secure FOTA) พร้อมระบบป้องกัน Rollback และการแบ่งเขตเน็ตเวิร์ก Zones & Conduits


      

        
1 · มาตรฐาน IEC 62443 Security Levels (SL) และ Zones & Conduits

        

          
ระดับความมั่นคง (Security Level)เป้าหมายและการคุกคาม (Threat Profile)ข้อกำหนดทางสถาปัตยกรรม (Architectural Requirements)

          

            SL 1 (Casual / Coincidental)
            ป้องกันความผิดพลาดจากการกระทำของผู้ปฏิบัติงาน หรือมัลแวร์ทั่วไป
            การตั้งรหัสผ่านพื้นฐาน, การปิดพอร์ตดีบักที่ไม่ใช้งาน (JTAG Lock)
          

          

            SL 2 (Simple Intent)
            ป้องกันผู้โจมตีที่มีทักษะต่ำและใช้เครื่องมือสำเร็จรูป
            การเข้ารหัสช่องทางสื่อสาร (TLS 1.3 บน Modbus TCP), ตรวจสอบสิทธิ์ผู้ใช้ตามบทบาท (RBAC)
          

          

            SL 3 (Sophisticated Intent)
            ป้องกันผู้โจมตีที่มีความเชี่ยวชาญสูงและมีแรงจูงใจทางการแข่งขัน
            ระบบ Secure Boot พร้อมตรวจสอบลายมือชื่อ ECDSA, การป้องกัน Rollback ด้วย Hardware E-Fuse
          

          

            SL 4 (Nation-State / Advanced)
            ป้องกันการโจมตีระดับองค์กรหรือรัฐบาลที่ใช้เทคโนโลยีขั้นสูงและทรัพยากรไม่จำกัด
            ฮาร์ดแวร์ Secure Element (e.g. ATECC608, TPM 2.0), Physical Tamper Resistance, TrustZone Memory Isolation
          

        

      


      

        
2 · ห่วงโซ่ความน่าเชื่อถือของการบูตระบบ (Secure Boot Chain of Trust)

        

          

            
สถาปัตยกรรมการตรวจสอบลายมือชื่อ (Cryptographic Authentication)

            
กระบวนการบูตต้องเริ่มจากพื้นที่ฮาร์ดแวร์ที่ไม่สามารถแก้ไขได้ (Immutable Root of Trust):

            
1. ROM Bootloader (เผาตายในชิป silicon):
   - อ่าน Public Key Hash จาก One-Time Programmable (OTP) E-Fuse
2. ตรวจสอบ Second-Stage Bootloader (MCUboot):
   - คำนวณ Hash SHA-256 ของไบนารี
   - ตรวจสอบลายมือชื่อ ECDSA-P256 หรือ Ed25519
3. ตรวจสอบ Application Firmware:
   - ตรวจสอบความถูกต้องของ Header, Image Signature และ Version Number
4. หากพบความผิดปกติแม้แต่บิตเดียว:
   - สั่ง Halt ระบบทันที และส่งสัญญาณแจ้งเตือนไปยัง Safety Interlock

          

          

            
การป้องกันการย้อนกลับเวอร์ชัน (Anti-Rollback Protection)

            
ผู้โจมตีมักพยายาม Flash เฟิร์มแวร์เวอร์ชันเก่าที่มีช่องโหว่ (Known CVEs) กลับเข้าไป เพื่อเจาะระบบ:

            
กลไกป้องกันด้วย Monotonic Hardware Counter:
- ทุกครั้งที่มีการ Release Firmware ใหม่:
  เลข Version ใน Header จะต้องสูงกว่าค่าใน E-fuse
- เมื่อบูตสำเร็จ: 
  Bootloader จะสั่งเผาบิต E-fuse เพิ่มขึ้น
- หากเลขเวอร์ชันใน Firmware ใหม่ < เลขใน E-fuse:
  Bootloader จะปฏิเสธการบูตและทำลาย Image นั้นทิ้ง

          

        

      


      

        
3 · การแบ่งกั้นหน่วยความจำด้วย ARM TrustZone-M และ MPU Configuration

        

          
กลไกฮาร์ดแวร์หน้าที่การทำงานการตั้งค่ารีจิสเตอร์เพื่อความปลอดภัยสูงสุด

          

            ARM TrustZone-M (SAU / IDAU)
            แบ่งซีพียูออกเป็นสองมิติ: Secure World (เก็บกุญแจคริปโต) และ Non-Secure World (รัน FreeRTOS/App)
            กำหนดให้พื้นที่คีย์ลับและฟังก์ชัน Cryptographic อยู่ในโซน Secure และเข้าถึงได้เฉพาะผ่าน Non-Secure Callable (NSC) Veneers
          

          

            MPU eXecute Never (XN Bit)
            ป้องกันการรันโค้ดแปลกปลอมจากหน่วยความจำ RAM (Shellcode Execution Prevention)
            ตั้งบิต XN = 1 บนทุก MPU Region ของ SRAM และ Peripheral Space เพื่อป้องกัน Buffer Overflow Exploits
          

          

            JTAG / SWD Readout Protection (RDP)
            ป้องกันการต่อสาย Debugger เพื่อดึงไบนารีหรือ Memory Dump ออกจาก Flash
            ตั้งค่า RDP Level 1 (ห้ามอ่าน Flash ผ่านดีบักเกอร์) หรือ RDP Level 2 (ล็อกถาวรในขั้นตอนส่งมอบโรงงาน)
          

        

      


      

        
4 · การสื่อสารทางอุตสาหกรรมที่ปลอดภัย (Industrial Protocol Hardening)

        

          

            
Modbus Security (IEC 62443-4-2 Compliance)

Predictive Maintenance (PdM) & Vibration Diagnostics (ISO 10816 / ISO 20816)

      
คู่มือมาตรฐานการตรวจวิเคราะห์ความสั่นสะเทือนเพื่อการบำรุงรักษาเชิงคาดการณ์ในโรงงานอุตสาหกรรม: ครอบคลุมสมการการแปลง FFT, ลายเซ็นความถี่บ่งชี้ความเสียหายทางกล (Unbalance, Misalignment, Looseness, Gearmesh), การถอดรหัส Envelope Demodulation สำหรับแบริ่งระยะเริ่มต้น และเกณฑ์ตัดหยุดฉุกเฉินตามมาตรฐาน ISO 10816-3


      

        
1 · ตารางลายเซ็นสเปกตรัมความถี่บ่งชี้ความผิดปกติทางกล (Mechanical Defect Signatures)

        

          
อาการผิดปกติ (Fault Mode)ยอดสเปกตรัมที่เด่นชัด (Dominant Frequencies)พฤติกรรมในโดเมนเวลาและเฟส (Phase & Time Characteristics)การวินิจฉัยแยกแยะ (Differentiation)

          

            Mass Unbalance
            1X RPM สูงโด่งในแนวรัศมี (Radial Horizontal & Vertical)
            สัญญาณรูปคลื่นไซน์บริสุทธิ์ (Pure Sine), มุมเฟสระหว่าง Horiz/Vert ห่างกัน ≈ 90°
            หากแก้ด้วยการทำ Dynamic Balancing ค่า 1X จะลดลงอย่างมีนัยสำคัญ
          

          

            Angular / Parallel Misalignment
            2X RPM สูงเด่นชัด ร่วมกับ 1X และ 3X ในแนวแกน (Axial)

            เกิดจากเพลาเยื้องศูนย์ ต้องทำเลเซอร์ตั้งศูนย์เพลา (Laser Alignment)
          

          

            Mechanical Looseness
            เกิดฮาร์มอนิกย่อย 0.5X, 1.5X, 2.5X, 3.5X และฮาร์มอนิกสูงยาวต่อเนื่อง
            รูปคลื่นเวลาถูกตัดยอด (Truncated / Impacting waveform) จากการกระแทก
            เกิดจากฐานยึดหลวม น็อตคลายตัว หรือระยะเผื่อเสื้อแบริ่งหลวมเกินพิกัด
          

          

            Gearmesh Failure (GMF)
            f_gmf = N_teeth * f_r พร้อมแถบความถี่ข้าง (Sidebands) ห่างเท่ากับ 1X

            จำนวน Sidebands และความสูงบ่งบอกระดับความสึกหรอของเฟืองขับ
          

        

      


      

        
2 · ฟิสิกส์ความถี่ข้อบกพร่องของตลับลูกปืน (Bearing Kinematics Equations)

        

          

            
สมการการคำนวณความถี่เฉพาะ (Kinematic Defect Equations)

            
คำนวณจากขนาดเส้นผ่านศูนย์กลาง Pitch (D), เม็ดลูกปืน (d), จำนวนเม็ด (n) และมุมสัมผัส (β):

            
BPFO (Outer Race):
BPFO = (n / 2) * f_r * [ 1 - (d / D) * cos(beta) ]

BPFI (Inner Race):
BPFI = (n / 2) * f_r * [ 1 + (d / D) * cos(beta) ]

BSF (Ball Spin):
BSF  = (D / (2 * d)) * f_r * [ 1 - ((d / D) * cos(beta))^2 ]

FTF (Cage / Fundamental Train):
FTF  = 0.5 * f_r * [ 1 - (d / D) * cos(beta) ]

          

          

            
การวิเคราะห์ Envelope Demodulation (Hilbert Transform)

            
ในระยะเริ่มต้น (Stage 1-2) รอยร้าวขนาดไมโครบนผิวแบริ่งจะไม่ปรากฏในย่านความถี่ต่ำ แต่จะกระตุ้นคลื่นสะท้อนความถี่สูง (Structural Resonance 2 kHz - 10 kHz):

            
ขั้นตอน Envelope Analysis:
1. นำสัญญาณผ่าน Band-pass Filter ย่านเรโซแนนซ์ (เช่น 3-5 kHz)
2. ทำการ Demodulate ผ่านการแปลงฮิลเบิร์ต (Hilbert Transform):
   z(t) = s(t) + j * H{s(t)}
   Envelope(t) = |z(t)|
3. รัน FFT ซ้ำบน Envelope สัญญาณ:
   ยอดความถี่ BPFO / BPFI จะโผล่ขึ้นมาอย่างเด่นชัด 
   ก่อนที่แบริ่งจะพังทลายล่วงหน้า 1 ถึง 3 เดือน!

Industrial Network Redundancy & High-Availability (PRP / HSR / TSN)

      
คู่มือมาตรฐานเครือข่ายอุตสาหกรรมที่มีความพร้อมใช้งานสูง (Mission-Critical High-Availability Ethernet) ตามมาตรฐาน IEC 62439-3: สถาปัตยกรรม Parallel Redundancy Protocol (PRP - Zero Failover Time), High-availability Seamless Redundancy (HSR), การเปรียบเทียบกับ RSTP และมาตรฐาน Time-Sensitive Networking (IEEE 802.1Q TSN)


      

        
1 · เปรียบเทียบเทคโนโลยีสำรองเครือข่ายอุตสาหกรรม (Network Redundancy Comparison)

        

          
โปรโตคอลมาตรฐานสากลเวลาฟื้นตัว (Recovery Time)โครงสร้างทอพอโลยี (Topology)พฤติกรรมเมื่อสายขาด (Fault Behavior)

          

            RSTP (Rapid Spanning Tree)
            IEEE 802.1w
            1 ถึง 2 วินาที (ขึ้นกับขนาด Ring)
            Ring หรือ Mesh สวิตช์ทั่วไป
            แพ็กเก็ตตกหล่นระหว่างคำนวณเส้นทางใหม่ ไม่เหมาะกับ Motion Control / Safety
          

          

            PRP (Parallel Redundancy)
            IEC 62439-3 Clause 4
            0 ms (Zero Failover Time)
            Dual Independent Active LANs (LAN A & LAN B)
            ไม่มีการกระตุกแม้แต่มิลลิวินาทีเดียว เพราะส่งข้อมูลพร้อมกันทั้งสองเครือข่าย
          

          

            HSR (High-availability Seamless)
            IEC 62439-3 Clause 5
            0 ms (Zero Failover Time)
            Ring Topology โดยไม่ต้องมี External Switch
            ส่งเฟรมแยกซ้าย-ขวาบนวงแหวนพร้อมกัน ปลายทางกำจัดเฟรมซ้ำทิ้งอัตโนมัติ
          

          

            TSN (Time-Sensitive Networking)
            IEEE 802.1Q (Qbv, CB)
            0 ms (Deterministic Scheduled)
            Bridge Network ร่วมกับ Time-Aware Shaper
            จัดสรรสลอตเวลาไมโครวินาที (TDMA) รับประกัน Latency และกำจัด Frame Loss
          

        

      


      

        
2 · กลไกการทำงานของ Parallel Redundancy Protocol (PRP)

        

          

            
สถาปัตยกรรมโหนดและการส่งแพ็กเก็ตคู่ขนาน (Duplicate Frame Mechanism)

            
อุปกรณ์ประเภท Dual Attached Node with PRP (DANP) จะเชื่อมต่อสายแลน 2 เส้นเข้ากับสองสวิตช์เน็ตเวิร์กที่แยกกันเด็ดขาด (LAN A และ LAN B):

            
1. ฝั่งส่ง (Transmitter):
   - ทำซ้ำแพ็กเก็ตเป็น 2 ชุดเหมือนกันทุกประการ
   - แปะตัวต่อท้าย Redundancy Control Trailer (RCT) ขนาด 6 ไบต์
   - ส่งออกพอร์ต A (LAN A) และพอร์ต B (LAN B) พร้อมกัน

2. ฝั่งรับ (Receiver):
   - ตรวจสอบ Sequence Number ใน RCT
   - แพ็กเก็ตใดมาถึงก่อน จะถูกส่งขึ้น Application Layer ทันที
   - แพ็กเก็ตที่สองที่มาถึงทีหลัง จะถูกทิ้ง (Discarded) ทันที

          

          

            
โครงสร้างส่วนต่อท้าย PRP RCT (Redundancy Control Trailer - 6 Bytes)

            

              
ไบต์ชื่อฟิลด์คำอธิบาย

              
0-1Sequence Numberเลขนับแพ็กเก็ต 16 บิต (0 ถึง 65535)

              
2LAN ID (4 bits) + Size (12 bits)LAN A = 0xA, LAN B = 0xB พร้อมขนาดเฟรม

              
4-5PRP Suffixค่าคงที่ 0x88FB บ่งชี้ว่าเป็นเฟรม PRP

            

          

        

      

    


  
    

      
A13
Industrial Instrumentation, Sensor Physics & Calibration (IEC 60751 / NAMUR NE 43)

      
คู่มือมาตรฐานวิศวกรรมเครื่องมือวัดอุตสาหกรรม (Industrial Instrumentation Engineering): ฟิสิกส์การวัดอุณหภูมิ RTD และเทอร์โมคัปเปิล, การชดเชยรอยต่อเย็น (Cold-Junction Compensation), การออกแบบลูปกระแส 4–20 mA, โปรโตคอลดิจิทัลซ้อนทับ HART และการกำจัดสัญญาณรบกวน Ground Loop ด้วย Galvanic Isolation


      

        
1 · ฟิสิกส์และสมการการแปลงอุณหภูมิ RTD (IEC 60751 / DIN EN 60751)

        

          

            
สมการ Callendar-Van Dusen (CVD) สำหรับทองคำขาว (Platinum RTD)

            
สำหรับช่วงอุณหภูมิบวก $t \ge 0^\circ	ext{C}$ (ความสัมพันธ์แบบพหุนามกำลังสอง):

            
R(t) = R0 * ( 1 + A*t + B*t^2 )

เมื่อ:
R0 = 100.00 Ω (PT100) หรือ 1000.00 Ω (PT1000)
A  = 3.9083 × 10^-3 °C^-1
B  = -5.7750 × 10^-7 °C^-2

การแก้สมการหาค่า t ย้อนกลับจากความต้านทาน R (Quadratic Inversion):
t = [ -A + sqrt( A^2 - 4*B*(1 - R/R0) ) ] / ( 2*B )

          

          

            
สมการสำหรับช่วงอุณหภูมิลบ $t < 0^\circ	ext{C}$

            
สำหรับช่วงอุณหภูมิลบ ต้องเพิ่มพจน์กำลังสี่ $C(t - 100)t^3$ เข้าไปด้วย:

            
R(t) = R0 * [ 1 + A*t + B*t^2 + C*(t - 100)*t^3 ]

เมื่อ:
C  = -4.1830 × 10^-12 °C^-4

ชั้นความถูกต้องตาม DIN EN 60751 (Tolerance Classes):
- Class AA (1/3 DIN): ±(0.10 + 0.0017 * |t|) °C
- Class A:            ±(0.15 + 0.0020 * |t|) °C
- Class B:            ±(0.30 + 0.0050 * |t|) °C

          

        

      


      

        
2 · สถาปัตยกรรมลูปกระแส 4–20 mA และโปรโตคอล HART (IEC 60381-1 / NAMUR NE 43)

        

          

            
การคำนวณแรงดันตกคร่อมในลูป (Loop Voltage Budget & Burden)

            
การต่อเซนเซอร์ 2-Wire Transmitter เข้ากับแหล่งจ่ายไฟ DC 24V ต้องมี Headroom เพียงพอ:

            
V_supply >= V_tx_min + ( I_max * ( R_sense + 2*R_wire ) ) + V_barrier

ตัวอย่างคำนวณ:
- V_supply = 24.0 V
- V_tx_min = 12.0 V (แรงดันทำงานขั้นต่ำของตัวส่งสัญญาณ)
- I_max    = 21.5 mA (พิกัดสูงสุดตาม NAMUR NE 43)
- R_sense  = 250.0 Ω (แปลง 4-20mA เป็น 1-5V ADC Input)
- R_wire   = 25.0 Ω (สายทองแดงยาว 500 เมตร)

V_drop_resistors = 0.0215 * ( 250 + 50 ) = 6.45 V
V_available_tx   = 24.0 - 6.45 = 17.55 V (> 12.0 V) -> ผ่านเกณฑ์ฉลุย!

          

          

            
โปรโตคอลสื่อสารดิจิทัลซ้อนทับ HART (Bell 202 FSK)

            
HART ทำงานโดยซ้อนทับสัญญาณ AC ขนาดเล็ก (±0.5 mA) ลงบนกระแสอะนาล็อก 4-20 mA:

            
ความถี่ FSK (Frequency Shift Keying):
- Mark (บิต 1): 1200 Hz
- Space (บิต 0): 2200 Hz
- Baud Rate: 1200 bps
- ค่าเฉลี่ย DC ของสัญญาณ AC เท่ากับ 0 พอดี:
  ทำให้การอ่านค่า Process Variable ด้วย ADC ไม่ถูกรบกวน!

ประโยชน์:
1. อ่านค่าตัวแปรรอง (เช่น อุณหภูมิภายในเซนเซอร์)
2. สอบเทียบ Zero & Span จากระยะไกลผ่าน Handheld Field Communicator
3. อ่านรหัสข้อผิดพลาดเชิงลึก (Self-Diagnostics)

2 · เทคนิคการป้องกันประกายไฟและแนวคิด Intrinsic Safety (Ex i)

        

          

            
กฎการจับคู่ Entity Parameters ของระบบ Intrinsic Safety

            
อุปกรณ์ในตู้ควบคุม (Associated Apparatus / Barrier) ต้องจ่ายพลังงานไม่เกินขีดจำกัดสูงสุดของอุปกรณ์ในพื้นที่อันตราย (Intrinsically Safe Field Device):

1. U_o <= U_i   (แรงดันวงจรเปิดของแผงกั้น <= แรงดันพิกัดของอุปกรณ์)
2. I_o <= I_i   (กระแสลัดวงจรของแผงกั้น <= กระแสพิกัดของอุปกรณ์)
3. P_o <= P_i   (กำลังไฟฟ้าสูงสุดของแผงกั้น <= กำลังงานพิกัด)
4. C_o >= C_i + C_cable  (ค่าความจุไฟฟ้าสะสมต้องไม่เกินขีดจำกัด)
5. L_o >= L_i + L_cable  (ค่าความเหนี่ยวนำสะสมต้องไม่เกินขีดจำกัด)
